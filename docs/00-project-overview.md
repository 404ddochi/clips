# CLIPS 프로젝트 개요

## 문서 목적

본 문서는 **CLIPS(클립스)** — 「이클립스: 더 어웨이크닝(Eclipse: The Awakening)」 비공식 팬 정보 사이트의 목표, 대상 독자, 가치, 공식 서비스와의 관계, 성공 지표, 비기능 요구사항(NFR)을 정의합니다.

---

## 서비스 정의

| 항목 | 내용 |
|------|------|
| 서비스명 | CLIPS / 클립스 |
| 대상 게임 | 이클립스: 더 어웨이크닝 |
| 성격 | **비공식** 팬 정보·아카이브 플랫폼 |
| 기술 스택 | FastAPI + Jinja2 SSR, SQLAlchemy, SQLite(로컬) / PostgreSQL(운영 권장) |
| 기본 언어 | 한국어(`ko`), 타임존 `Asia/Seoul` |

CLIPS는 공식 홈페이지를 **대체**하지 않습니다. 공지·패치·이벤트를 **한국어 사용자 관점에서 빠르게 찾고 비교**할 수 있도록 정리·링크·요약을 제공하는 **보조 정보 허브**입니다.

---

## 확정

### 목적(Purpose)

1. **검색 친화적 정보 허브**: 클래스, 콘텐츠, 아이템, 보스, 지도, 공략, 쿠폰 등 게임 플레이에 필요한 정보를 **SSR HTML**로 제공하여 Google·Naver·Bing 등 검색 엔진이 콘텐츠를 안정적으로 수집·색인할 수 있게 한다.
2. **소식 집약**: 공지, 업데이트(패치 노트), 이벤트를 시간순·카테고리별로 모아 **“오늘 게임에서 무슨 일이 있었는지”**를 한 화면에서 파악하게 한다.
3. **출처 투명성**: 공식 원문·공식 채널 링크를 명시하고, 비공식 사이트임을 상시 고지한다.
4. **운영 가능한 구조**: 크롤러·관리자·통계 도메인을 문서·스키마 수준에서 분리 설계하여, 콘텐츠가 늘어나도 유지보수 비용을 통제한다.

### 대상 독자(Audience)

| 세그먼트 | 니즈 | CLIPS가 제공할 가치 |
|----------|------|---------------------|
| 신규·복귀 유저 | 직업 선택, 성장 루트, 필수 콘텐츠 | 클래스·콘텐츠·공략 요약, 내부 링크 구조 |
| 일상 플레이어 | 패치 반영, 이벤트 마감, 쿠폰 | 소식 허브, 쿠폰 목록, 알림(향후) |
| 수집·경제 유저 | 드랍, 재료, 시세(비공식) | 아이템·보스·지도 DB, 출처 표기 |
| 검색 유입 방문자 | 특정 키워드(보스명, 스킬명 등) | SEO 최적화된 상세 페이지, canonical·구조화 데이터 |
| 운영진·기여자 | 데이터 정확도, 수정 이력 | 관리자 API·감사 로그(향후) |

### 핵심 가치(Values)

- **SEO-first**: 모든 공개 페이지는 서버 렌더링, 의미 있는 `<title>`·description·canonical·robots·JSON-LD를 기본 탑재한다.
- **정확성과 겸손**: 추측과 팬 해석은 “가이드/커뮤니티” 영역으로 구분하고, 공식 수치·공지는 **source** 도메인과 연결한다.
- **접근성·성능**: 모바일 우선 레이아웃, Core Web Vitals를 문서·구현 양쪽에서 추적한다.
- **법적·브랜드 존중**: 게임명·에셋은 각 권리자 소유임을 명시하고, 공식 로고·원본 미디어 무단 호스팅을 지양한다.

### 공식 사이트와의 관계

- CLIPS는 **팬 프로젝트**이며 공식 운영사·퍼블리셔와 **제휴·승인 관계가 없음**을 푸터·메타·About(향후)에 명시한다.
- 공지·패치 본문은 가능한 한 **공식 URL로 링크**하고, CLIPS DB에는 요약·메타·색인용 텍스트·크롤 메타를 저장하는 방향을 우선한다(전문 재게시 범위는 향후 법무·정책 검토).
- 공식 사이트 구조 변경 시 크롤러(`crawl_log`, `source`)로 장애를 감지하고 수동 패치 절차를 문서화한다.

### 초기 목표(Phase 0 ~ 1, 코드베이스 기준)

- 홈 SSR, 공통 레이아웃(헤더·푸터), SEO 메타 컴포넌트, `robots.txt` / `sitemap.xml`, JSON-LD(WebSite·WebPage).
- 섹션 라우트(`/news`, `/classes`, …) **준비 중(preparing)** 페이지 — `noindex, follow`로 색인 정책 분리.
- Alembic·SQLAlchemy 기반 DB 골격, 환경별 설정(`APP_BASE_URL`, `DATABASE_URL`).

### 장기 목표(Phase 2+)

- 도메인별 CRUD·상세 SSR 페이지 전면 개방 및 sitemap 동적 생성.
- 공식 공지·이벤트 크롤/동기화 파이프라인, 관리자 CMS-lite.
- 통합 검색(내부 + search_term 통계), 조회수·인기 콘텐츠.
- RSS/Atom 피드, 다국어(일본어·영어)는 **우선순위 낮음**.

### 성공 지표(Success Metrics)

| 영역 | 지표 | 비고 |
|------|------|------|
| 검색 | 색인 페이지 수, 클릭 CTR, 평균 순위(브랜드·롱테일) | Search Console, Naver Search Advisor |
| 트래픽 | 유기적 세션 비율, 직접 유입, 재방문율 | GA4 또는 Plausible(향후) |
| 콘텐츠 | 섹션별 publish 비율, 최종 수정일 freshness | 내부 대시보드 |
| 품질 | 404 비율, 크롤 오류율, 사용자 신고 건수 | crawl_log, 지원 채널 |
| 성능 | LCP, INP, CLS (p75) | RUM 또는 Lighthouse CI |

### 비기능 요구사항(NFR)

| ID | 요구사항 | 확정 수준 |
|----|----------|-----------|
| NFR-SEO-01 | 공개 콘페이지 `index, follow` + canonical | 확정 |
| NFR-SEO-02 | 준비 중·오류 페이지 `noindex` | 확정 |
| NFR-SEC-01 | 운영 환경 기본 `SECRET_KEY` 금지, `APP_DEBUG=false` | 확정(코드 검증) |
| NFR-SEC-02 | Security 헤더(X-Content-Type-Options, X-Frame-Options 등) | 확정 |
| NFR-AVAIL-01 | 헬스체크 `/health` | 확정 |
| NFR-PERF-01 | TTFB·LCP 목표는 `06-seo-strategy.md` CWV 절 참조 | 확정(목표값) |
| NFR-SCALE-01 | Stateless 앱 + PostgreSQL, 정적 자산 CDN | 향후 결정(CDN 벤더) |

## 향후 결정

- **법적 고지문** 최종 문안(변호사 검토 여부, DMCA/저작권 문의 창구).
- **수익화**: 광고, 후원, 프리미엄 기능 유무 및 공식 IP 가이드라인 준수 방식.
- **UGC**: 댓글·위키式 편집 허용 범위, 모더레이션 정책.
- **실시간 데이터**: 서버 상태·큐 대기 등 공식 API 없을 때 표시 정책.
- **다국어** 우선순위 및 hreflang 전략.
